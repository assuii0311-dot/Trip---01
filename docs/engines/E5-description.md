# E5. 장소 설명 생성 엔진

- 상태: 설계 동의 (2026-10-25, D-025)
- 관련 요구사항: R-16 (보조: R-20 한국어 명칭, R-05 지역 요약의 한국어)
- 관련 결정: D-001, D-012, D-013, D-021
- 설계 시점: 3단계
- 작성일: 2026-10-25
- 최종 수정일: 2026-10-25 (설계 동의 반영)

> 요구사항 6절의 절차(생성 엔진 계획, 대표 모수 생성, 검수와 수정, 전수 적용)를 따르는 초안이다. 출처 커버리지는 `docs/02-poc-results.md` 16절, 라이선스 표기는 D-021 ⑦.

## 1. 목적

- 개발 시점에 영어·스페인어 출처 텍스트로 장소별 한국어 요약과 상세 설명을 생성하고 출처와 라이선스를 표기한다(R-16). 대상은 1등급과 2등급 장소 전체와 도시·지역 요약이다(D-024). 생성은 순서대로 진행하고 아직 생성되지 않은 장소는 원문 요약을 보인다. 데이터에 없는 한국어 명칭을 생성한다(R-20 보조). 도시·지역 요약의 한국어본도 같은 방식으로 만든다(R-05 보조).
- 용도는 여행 중 현장에서 읽어 장소를 파악하는 것이다. 짧은 문장, 출처에 있는 사실만, 추정 금지.
- 경계: 출처 텍스트 수집은 E1, 음성은 브라우저 합성(R-17), 추천 근거 문장은 E2. 영업시간·가격·예약은 데이터 필드로 따로 표시하므로 본문에 넣지 않는다.

## 2. 입력

| 입력 | 출처 | 필수 |
|---|---|---|
| 설명 출처 텍스트: Wikivoyage 목록 content와 Understand 절(영어, 스페인어), 위키백과 발췌(en, es, ko), Wikidata 설명 | E1 description_sources | 필수 |
| 장소 메타: 명칭(현지어·영어·한국어 유무), 범주, 유산 지정, 도시 | E1 | 필수 |
| 생성 순서 | 4절 1항(범위는 전체, D-024) | 필수 |
| 스타일 지침과 길이 한도 | 4절 3항 | 필수 |
| 검수 결과(대표 모수) | 사용자 | 필수(전수 적용 전) |

## 3. 출력

| 필드 | 내용 |
|---|---|
| description_ko_summary | 2~3문장, 200자 이내 |
| description_ko_detail | 1,200자 이내. 소제목 없이 단락 2~4개 |
| name_ko, name_ko_source | 데이터에 없을 때 생성한 한국어 명칭과 "generated" 표시 |
| generated_from | 사용한 출처 목록(URL, 언어, 라이선스), 생성일, 생성 수단 |
| source_count, confidence, basis | 출처 수와 신뢰도(출처 2개 이상 일치=높음, 1개=보통, 태그만=태그 기반), 근거 종류(text 또는 tags) |
| attribution_text | 화면 표기 문구. Wikivoyage 기반이면 "출처: Wikivoyage(CC BY-SA 4.0)" 링크 포함(D-021 ⑦) |

소비자: 화면(장소 상세, 일정표), 음성 합성(R-17), E2(지역 요약 한국어).

## 4. 규칙과 알고리즘

1. 생성 범위(D-024 확정): 1등급과 2등급 장소 전체, 도시·지역 요약 전체. 1차·2차 구분은 두지 않는다. 생성은 한 번에 끝나지 않으므로 순서만 둔다(사용자 결정: 작업 시간 문제로 범위를 줄이지 않는다).
   - 순서: (1) 사용자가 입력한 여행 도시의 장소, (2) 영문 Wikivoyage 수록 볼거리·활동(사실: see 2,630 + do 1,044 = 3,674건), (3) 해외 대표 명소(E2 구분. 사실: PoC 조회수 보유 문서 19,049건 중 영어 비중 0.5 이상·사이트링크 10 이상 369건), (4) 유네스코 세계유산 지정(사실: Wikidata P1435에 Q9259 보유 91건), (5) 나머지 1등급, (6) 2등급. 도시·지역 요약(약 500건)은 (1)과 함께.
   - 미생성 장소의 표시: 출처 텍스트가 있으면 영어 원문 첫 두 문장, 없으면 범주·지역·OSM 태그로 만든 한 줄 요약(태그 기반). 제품 기능은 처음부터 전체에 제공되고 내용만 순서대로 채워진다.
   - 2등급 장소(식당·카페·상점 등)는 대부분 출처 텍스트가 없고 OSM 태그(범주, 음식 종류, 영업시간, 웹사이트)만 있다. 이 경우 요약 1~2문장만 태그에서 생성하고 상세는 만들지 않으며 basis=tags, 신뢰도 "태그 기반"으로 표시한다. 이 규칙은 "출처에 있는 사실만" 원칙을 지키기 위한 클로드의 해석이며 설계 동의 때 확인한다.
2. 생성 수단과 처리량(결정 필요, 제안): 개발 세션 안에서 클로드가 생성한다. 별도 API 과금이 없고 D-001(유료 데이터 미사용)과 서버 비용 0에 맞다. 처리량은 대표 모수 30곳을 만들 때 시간당 건수로 측정하고, 전체 건수(E1 결과)로 나눠 완료 예상일을 `docs/02-schedule-estimate.md`에 기록한다. 측정 전에는 완료일을 약속하지 않는다. 추정: 1등급 5~7만 건에 2등급 수십만 건을 더하면 요약만으로도 수천만 자여서 11월 20일 뒤까지 이어진다. 11월 계획 수립에는 순서 (1)~(4)가 먼저 채워지면 된다.
3. 스타일 지침: 한국어 평서문, 문장 20단어 안팎. 출처에 있는 사실만 쓰고 평가어("아름다운", "꼭 가야 할")는 쓰지 않는다. 숫자(연도, 높이, 규모)는 출처 그대로. 두 출처가 다르면 그 항목은 생략한다. 고유명사는 첫 등장에 원어를 괄호로 한 번 병기한다. 영업시간·가격·예약·교통은 쓰지 않는다(데이터 필드).
4. 한국어 명칭 생성 규칙: 한국어 위키백과 제목이 있으면 그것을 쓴다(생성 아님). 없으면 외래어 표기법에 따라 음차하고 보통명사 부분은 번역한다(예: "Museo de la Ciudad" → "시립 박물관(Museo de la Ciudad)"). 바스크어·카탈루냐어 명칭은 현지 명칭을 기준으로 음차한다(D-021 ⑥). 생성 명칭은 name_ko_source=generated로 표시한다.
5. 절차(요구사항 6절): (a) 생성 계획 문서화(이 문서의 설계 동의). (b) 대표 모수: 층화 표본 30곳(대도시·중소·소도시 각 10곳)과 도시 요약 6곳을 생성한다. (c) 사용자 검수: 사실 오류, 읽기 쉬움, 길이를 확인하고 수정 지시를 받는다. 지침을 고친다. (d) 전수 적용: 1차 범위를 생성하고 무작위 표본 30곳을 다시 검수한다. (e) 2차 범위는 일정 여유가 있을 때.
6. 재생성: 출처 텍스트가 바뀐 장소(E1 갱신 비교)만 다시 생성한다. 사용자가 수정한 설명은 보존 표시를 두고 덮어쓰지 않는다.
7. 출처 없음: 출처 텍스트가 없고 OSM 태그만 있으면 1항의 태그 기반 요약을 만든다. 태그도 명칭·범주뿐이면 생성하지 않고 "출처 텍스트 없음"과 명칭·범주·유산 지정만 표시한다.

## 6. 품질 기준과 평가 방법

| 기준 | 목표 | 측정 |
|---|---|---|
| 사실 정확성 | 표본 30곳에서 출처와 다른 서술 0건 | 클로드가 출처 대조, 사용자가 표본 재확인 |
| 길이 | 요약 200자, 상세 1,200자 한도 준수 100% | 자동 검사 |
| 출처 표기 | 생성 설명 100%에 attribution_text | 자동 검사 |
| 가독성 | 사용자 평가 5점 만점 4점 이상(표본 30곳 평균) | 검수 기록 |
| 금지 항목 | 영업시간·가격·예약 서술 0건, 평가어 0건 | 자동 검사(단어 목록) + 표본 검수 |

## 7. 대안 사다리

| 상황 | 대안 |
|---|---|
| 생성량 부족(세션 한도) | 범위는 줄이지 않는다. 순서대로 진행하고 미생성 장소는 원문·태그 요약을 표시하며 완료 예상일을 다시 산출한다 |
| 출처 1개뿐 | 생성하되 신뢰도 "보통"과 단일 출처 표시 |
| 출처 없음 | 생성 안 함. 명칭·범주만 |
| 한국어 명칭 생성 불확실 | 원어만 표시 |

## 8. 관련 결정

- D-001 유료 데이터 미사용. D-012 엔진 분리. D-013 대안 사다리. D-021 ⑥(현지 명칭), ⑦(라이선스 표기). D-024(생성 범위 전체).
- D-024 확정: (a) 생성 범위는 1·2등급 전체와 요약, 순서는 4절 1항.
- D-025(2026-10-25 설계 동의)로 제안값 확정: (b) 생성 수단(개발 세션 안 클로드)과 처리량 측정 뒤 완료일 채택, (c) 길이 한도 200자·1,200자, (d) 한국어 명칭 표기 규칙, (e) 대표 모수 표본 수 30 + 6, (f) 2등급의 태그 기반 요약 규칙(4절 1항, 클로드 해석).
