# E5. 장소 설명 생성 엔진

- 상태: 설계 동의 (2026-10-25, D-025)
- 관련 요구사항: R-16 (보조: R-20 한국어 명칭, R-05 지역 요약의 한국어)
- 관련 결정: D-001, D-012, D-013, D-021, D-024, D-025, D-032
- 설계 시점: 3단계
- 작성일: 2026-10-25
- 최종 수정일: 2026-11-14 (여행지 소개 절차 추가, D-032)

> 요구사항 6절의 절차(생성 엔진 계획, 대표 모수 생성, 검수와 수정, 전수 적용)를 따르는 초안이다. 출처 커버리지는 `docs/02-poc-results.md` 16절, 라이선스 표기는 D-021 ⑦.

## 1. 목적

- 개발 시점에 영어·스페인어 출처 텍스트로 장소별 한국어 요약과 상세 설명을 생성하고 출처와 라이선스를 표기한다(R-16). 대상은 1등급과 2등급 장소 전체와 도시·지역 요약이다(D-024). 생성은 순서대로 진행하고 아직 생성되지 않은 장소는 원문 요약을 보인다. 데이터에 없는 한국어 명칭을 생성한다(R-20 보조). 도시·지역 요약의 한국어본도 같은 방식으로 만든다(R-05 보조).
- 용도는 여행 중 현장에서 읽어 장소를 파악하는 것이다. 짧은 문장, 출처에 있는 사실만, 추정 금지.
- 경계: 출처 텍스트 수집은 E1, 음성은 브라우저 합성(R-17), 추천 근거 문장은 E2. 영업시간·가격·예약은 데이터 필드로 따로 표시하므로 본문에 넣지 않는다.

## 2. 입력

| 입력 | 출처 | 필수 |
|---|---|---|
| 설명 출처 텍스트: Wikivoyage 목록 content와 Understand 절(영어, 스페인어), 위키백과 발췌(en, es, ko), Wikidata 설명 | E1 description_sources | 필수 |
| 장소 메타: 명칭(현지어·영어·한국어 유무), 범주, 유산 지정, 도시 | E1 | 필수 |
| 생성 순서 | 4절 1항(범위는 전체, D-024) | 필수 |
| 스타일 지침과 길이 한도 | 4절 3항 | 필수 |
| 검수 결과(대표 모수) | 사용자 | 필수(전수 적용 전) |

## 3. 출력

| 필드 | 내용 |
|---|---|
| description_ko_summary | 2~3문장, 200자 이내 |
| description_ko_detail | 1,200자 이내. 소제목 없이 단락 2~4개 |
| name_ko, name_ko_source | 데이터에 없을 때 생성한 한국어 명칭과 "generated" 표시 |
| generated_from | 사용한 출처 목록(URL, 언어, 라이선스), 생성일, 생성 수단 |
| source_count, confidence, basis | 출처 수와 신뢰도(출처 2개 이상 일치=높음, 1개=보통, 태그만=태그 기반), 근거 종류(text 또는 tags) |
| attribution_text | 화면 표기 문구. Wikivoyage 기반이면 "출처: Wikivoyage(CC BY-SA 4.0)" 링크 포함(D-021 ⑦) |

소비자: 화면(장소 상세, 일정표), 음성 합성(R-17), E2(지역 요약 한국어).

## 4. 규칙과 알고리즘

1. 생성 범위(D-024 확정): 1등급과 2등급 장소 전체, 도시·지역 요약 전체. 1차·2차 구분은 두지 않는다. 생성은 한 번에 끝나지 않으므로 순서만 둔다(사용자 결정: 작업 시간 문제로 범위를 줄이지 않는다).
   - 순서: (1) 사용자가 입력한 여행 도시의 장소, (2) 영문 Wikivoyage 수록 볼거리·활동(사실: see 2,630 + do 1,044 = 3,674건), (3) 해외 대표 명소(E2 구분. 사실: PoC 조회수 보유 문서 19,049건 중 영어 비중 0.5 이상·사이트링크 10 이상 369건), (4) 유네스코 세계유산 지정(사실: Wikidata P1435에 Q9259 보유 91건), (5) 나머지 1등급, (6) 2등급. 도시·지역 요약(약 500건)은 (1)과 함께.
   - 미생성 장소의 표시: 출처 텍스트가 있으면 영어 원문 첫 두 문장, 없으면 범주·지역·OSM 태그로 만든 한 줄 요약(태그 기반). 제품 기능은 처음부터 전체에 제공되고 내용만 순서대로 채워진다.
   - 2등급 장소(식당·카페·상점 등)는 대부분 출처 텍스트가 없고 OSM 태그(범주, 음식 종류, 영업시간, 웹사이트)만 있다. 이 경우 요약 1~2문장만 태그에서 생성하고 상세는 만들지 않으며 basis=tags, 신뢰도 "태그 기반"으로 표시한다. 이 규칙은 "출처에 있는 사실만" 원칙을 지키기 위한 클로드의 해석이며 설계 동의 때 확인한다.
2. 생성 수단과 처리량(결정 필요, 제안): 개발 세션 안에서 클로드가 생성한다. 별도 API 과금이 없고 D-001(유료 데이터 미사용)과 서버 비용 0에 맞다. 처리량은 대표 모수 30곳을 만들 때 시간당 건수로 측정하고, 전체 건수(E1 결과)로 나눠 완료 예상일을 `docs/02-schedule-estimate.md`에 기록한다. 측정 전에는 완료일을 약속하지 않는다. 추정: 1등급 5~7만 건에 2등급 수십만 건을 더하면 요약만으로도 수천만 자여서 11월 20일 뒤까지 이어진다. 11월 계획 수립에는 순서 (1)~(4)가 먼저 채워지면 된다.
3. 스타일 지침: 한국어 평서문, 문장 20단어 안팎. 출처에 있는 사실만 쓰고 평가어("아름다운", "꼭 가야 할")는 쓰지 않는다. 숫자(연도, 높이, 규모)는 출처 그대로. 두 출처가 다르면 그 항목은 생략한다. 고유명사는 첫 등장에 원어를 괄호로 한 번 병기한다. 영업시간·가격·예약·교통은 쓰지 않는다(데이터 필드).
4. 한국어 명칭 생성 규칙: 한국어 위키백과 제목이 있으면 그것을 쓴다(생성 아님). 없으면 외래어 표기법에 따라 음차하고 보통명사 부분은 번역한다(예: "Museo de la Ciudad" → "시립 박물관(Museo de la Ciudad)"). 바스크어·카탈루냐어 명칭은 현지 명칭을 기준으로 음차한다(D-021 ⑥). 생성 명칭은 name_ko_source=generated로 표시한다.
5. 절차(요구사항 6절): (a) 생성 계획 문서화(이 문서의 설계 동의). (b) 대표 모수: 층화 표본 30곳(대도시·중소·소도시 각 10곳)과 도시 요약 6곳을 생성한다. (c) 사용자 검수: 사실 오류, 읽기 쉬움, 길이를 확인하고 수정 지시를 받는다. 지침을 고친다. (d) 전수 적용: 1차 범위를 생성하고 무작위 표본 30곳을 다시 검수한다. (e) 2차 범위는 일정 여유가 있을 때.
6. 재생성: 출처 텍스트가 바뀐 장소(E1 갱신 비교)만 다시 생성한다. 사용자가 수정한 설명은 보존 표시를 두고 덮어쓰지 않는다.
7. 출처 없음: 출처 텍스트가 없고 OSM 태그만 있으면 1항의 태그 기반 요약을 만든다. 태그도 명칭·범주뿐이면 생성하지 않고 "출처 텍스트 없음"과 명칭·범주·유산 지정만 표시한다.
8. 여행지 소개(D-032): 여행지 목록(E1 4절 15항)의 도시와 섬마다 한국어 요약을 만든다. 출처는 영문 Wikivoyage 가이드 문서의 머리글과 Understand 절이며 3항의 스타일 지침을 따른다. 요약은 여행지 이름으로 시작하고, 이름의 원어는 카드 제목에 있으므로 본문에서 다시 병기하지 않는다. 한국어 이름이 없는 여행지는 4항에 따라 한글 이름을 만든다(카탈루냐어·발렌시아어 공식 명칭은 현지 발음을 기준으로 음차). 생성본은 저장소의 내용 파일(pipeline/e5/content/destinations_ko.jsonl: id, 출처 문서, 요약, 이름, 출처 해시, 생성일)에 두고, pipeline/e5/destinations.py가 검증해 data/e5/destinations.json.gz로 내보낸다. 검증 항목은 길이 200자, 평서문 끝, 금지어(평가어와 영업시간·가격·예약), 출처 해시다. 출처 문서의 머리글이나 Understand 절이 바뀌면 해시가 달라지므로 그 여행지는 내보내지 않고(앱은 영문 원문을 보인다) 다시 대조한다(6항). 출처가 하나이므로 신뢰도는 "보통", 근거는 text다.

9. 장소 설명(D-033):
   - 표본: 대표 모수 30곳은 pipeline/e5/sample.py가 뽑는다. 층(대도시·중소 관광 도시·소도시)마다 10곳, 후보는 1등급이고 대표 범주가 볼거리이며 글 출처가 있는 장소, 순서는 md5(장소 ID), 한 도시 2곳·한 층의 같은 범주 4곳까지, 대도시 층의 5곳은 해외 대표 명소. 같은 입력에 같은 표본이 나온다.
   - 출처 묶음: 장소 레코드의 desc에 적힌 순서대로 Wikivoyage 목록 본문(data/sources), 위키백과 머리 문단(E1 보조 수집, 저장소 밖), Wikidata 설명. 묶음의 해시(src_md5)가 내용 파일에 적힌 값과 다르면 그 장소는 내보내지 않는다(6항).
   - 작성: 요약은 모든 대상 장소에 만들고 장소 이름으로 시작한다. 상세는 출처에 요약 밖의 사실이 두 단락 이상 나올 만큼 있을 때만 만든다(단락 2~4개, 소제목 없음). 장소 자신의 원어 이름은 본문에 병기하지 않는다(화면 제목에 있다). 출처끼리 다른 수치와 시점에 따라 바뀌는 사실은 뺀다.
   - 한글 이름: 4항을 따른다. 성인 이름이 든 성당 이름도 음차하고 뜻은 요약 첫 문장에 괄호로 적는다.
   - 저장과 내보내기: 내용 파일 pipeline/e5/content/places_ko.jsonl(id, 요약, 상세, 이름, 출처 해시, 생성일. 상세의 단락은 줄바꿈으로 나눈다) → pipeline/e5/places.py가 검증 → data/e5/places/<샤드>.json.gz(샤드는 md5(장소 ID) 앞 두 자리)와 data/e5/index.json(설명이 있는 샤드 목록, 생성한 한글 이름). 검증 항목은 요약 200자, 상세 1,200자와 단락 2~4개, 평서문 끝, 금지어, 출처 해시다. 같은 입력에 같은 바이트가 나온다.
   - 신뢰도: 글 출처의 종류 수. Wikivoyage와 위키백과가 모두 있으면 "높음", 하나면 "보통". 위키백과의 여러 언어판은 한 종류로 세고 Wikidata 설명은 세지 않는다.
   - 표시: 앱은 시작할 때 색인을 읽어 생성 이름을 붙이고("생성" 표시), 장소 상세에서 그 장소의 샤드를 읽어 요약·상세(접힘)·신뢰도·출처 링크·라이선스·생성본 표시를 보인다. 설명이 없는 장소는 1항의 미생성 표시를 그대로 쓴다.
   - 듣기(R-17): 브라우저 음성 합성으로 이름, 요약, 상세를 문장 단위로 읽는다. 한국어 기기 내장 음성만 쓰고 원격 음성은 쓰지 않는다. 괄호 안의 원어 병기는 읽지 않는다. 글을 다듬는 함수는 app/src/util/speech.js의 순수 함수다.
   - 대표 모수 결과(사실, 2026-11-14): 30곳의 출처 원문 합계 33,875자. 요약 30건(평균 122자, 최대 189자), 상세 13건(평균 352자, 최대 577자), 한글 이름 27건. 신뢰도 높음 7곳, 보통 23곳. 출처 읽기와 생성에 약 8분, 대조에서 5건 수정. 나머지 17곳은 출처가 한두 문장이라 요약만 있다.
   - 전체 규모(사실, 2026-11-14 데이터): 1등급 101,674곳 중 글 출처가 있는 곳 21,692곳(Wikivoyage 5,157, 위키백과 17,954, 둘 다 1,419), Wikidata 설명만 있는 곳 65,869곳, 출처 없음 14,113곳. 1항의 순서 (2)~(4)에 드는 곳은 합쳐 5,089곳(영문 Wikivoyage 4,885, 해외 대표 명소 269, 유네스코 90), 여행지 목록 111곳 안의 1등급 중 글 출처가 있는 곳은 8,723곳이다.
10. 전수 생성(D-038):
   - 대상 고르기: pipeline/e5/scope.py. 여행지마다 볼거리 범주 1등급 장소의 대표성(사이트링크 → 월조회수 → ID) 상위 N곳과 대표 명소. 여러 여행지에 걸친 장소는 순위가 앞선 여행지에 한 번만 넣는다. 첫 범위는 N=10, 글 출처가 있는 곳.
   - 묶음: `e5.places chunks`가 장소 40곳 이하, 출처 48,000자 이하로 나눈다. 묶음 파일에는 출처 하나를 2,200자까지만 싣고 출처 해시는 전문으로 계산한다.
   - 작성: 작업자가 pipeline/e5/content/GUIDE.md를 따라 묶음마다 부분 파일을 쓴다. 만들 수 없는 장소는 사유와 함께 건너뛴다.
   - 검사와 병합: `e5.places check`(형식) → 표본 대조(사실) → `e5.places merge` → `e5.places build`.
   - 검수: 범위 하나를 마치면 무작위 30곳의 검수표를 낸다(5항 (d)).
11. 한 줄 설명(D-039): `e5.places build`가 요약의 첫 문장("다." 뒤가 공백이거나 글의 끝인 첫 자리까지)을 모아 data/e5/lines.json.gz로 내보낸다. 앱은 목록 카드와 여행지 카드의 대표 명소에 쓴다. 그래서 요약의 첫 문장은 그것만 읽어도 무엇인지 알 수 있게 쓴다(GUIDE.md).
