# E0. 엔진 이름

- 상태: 초안
- 관련 요구사항: R-00
- 관련 결정: D-012
- 설계 시점: 2단계 PoC와 병행 또는 3단계
- 작성일: YYYY-MM-DD
- 최종 수정일: YYYY-MM-DD

> 이 템플릿을 복사해 `docs/engines/E<번호>-<영문 이름>.md`로 저장한다. 절은 삭제하지 않는다. 해당 사항이 없으면 "해당 없음"과 그 이유를 쓴다. 절 이름은 D-012에 정한 아홉 개와 같다.

## 1. 목적

이 엔진이 해결하는 문제와 책임 범위. 다른 엔진과의 경계. 어떤 요구사항의 어느 부분을 맡는지.

## 2. 입력

입력 항목, 형식, 출처(사용자 입력, 다른 엔진의 출력, 데이터). 필수와 선택을 구분한다.

## 3. 출력

출력 항목, 형식, 소비자(화면, 다른 엔진). 대안을 내는 엔진이면 대안의 수준과 개수를 적는다.

## 4. 규칙과 알고리즘

처리 단계. 판단 기준과 가중치. 의사코드 또는 단계 목록. 사용자 결정이 필요한 매개변수는 "결정 필요"로 표시한다.

## 5. 데이터 의존

사용하는 데이터 소스, 라이선스와 출처 표기 의무, 호출 한도, 갱신 주기. 2단계 PoC 결과(추출 가능, 불확실, 추출 불가)를 참조한다.

## 6. 품질 기준과 평가 방법

무엇을 "잘 동작한다"고 볼지의 측정 가능한 기준. 평가용 표본과 절차. 검수 방식(대표 모수 검수 후 전수 적용).

## 7. 대안 사다리

데이터나 방법이 부족할 때의 단계별 대안(A, B, C). 각 단계의 조건과 전환 기준(D-013). 어느 단계도 불가할 때의 재논의 지점.

## 8. 관련 결정

D-번호와 한 줄 요약. 이 문서에서 새로 필요한 결정은 "결정 필요"로 표시한다.

## 9. 상태

상태 값은 초안, 설계 동의, PoC 중, 구현 중, 검수 중, 완료의 순서로 바뀐다. 구현은 "설계 동의" 이후에만 시작한다.
