# E1. 데이터 수집·정규화 엔진

- 상태: 설계 동의 (2026-10-25, D-023)
- 관련 요구사항: R-03, R-04, R-20 (보조: R-16 출처 텍스트 공급, R-26 가격 필드 공급)
- 관련 결정: D-001, D-012, D-013, D-016, D-020, D-021
- 설계 시점: 2단계 PoC와 병행
- 작성일: 2026-10-25
- 최종 수정일: 2026-10-25 (설계 동의 반영)

> 2단계 PoC(`docs/02-poc-results.md`, `docs/02-poc-classification.md`)와 데이터 모델 초안(`docs/02-data-model.md`)을 바탕으로 작성한 초안이다. "결정 필요" 항목은 설계 동의 때 함께 정한다.

## 1. 목적

- 2단계에서 확정한 무료 소스에서 도시, 지역, 장소와 그 명칭, 분류, 좌표, 영업시간, 가격, 설명 출처, 관심도 신호를 수집하고, 다중 출처 교차검증을 거쳐 하나의 기준 데이터로 정규화한다. 취향 선택지(R-03)에 쓸 상위 분류 체계를 도출한다.
- 개발 시점에 개발 환경에서 실행하는 파이프라인이다. 결과는 앱 저장소에 정적 파일로 들어가고(D-011), 앱은 읽기만 한다.
- 경계: 추천 점수(E2), 이동 시간(E3), 한국어 설명 생성(E5), 비용 계산(E6)은 하지 않는다. 그 엔진들이 쓰는 입력 필드를 채우는 데서 끝난다. 엔진별로 나누면 다음과 같다.

| 엔진 | E1이 채워 주는 것 (데이터) | E1이 하지 않는 것 (판단·계산) |
|---|---|---|
| E2 추천 | 장소의 상위 범주, 문화유산 지정, 사이트링크 수, 언어별 월평균 조회수, 검증 여부, 교차검증 상태, 도시의 숙박 밀도와 가격대 분포 | 취향 대조와 점수·순위, 세 수준 대안 선정, 숙박 지역 추천, 예약 필요 여부 판단, 해외 대표 명소 점수의 공식 |
| E3 이동 | 장소·도시 좌표, 장소의 소속 도시, 도시별 GTFS 피드 목록과 라이선스, 택시 요금표 | 경로 그래프 구축, GTFS 노선·정류장·운행 시간 파싱, 소요 시간과 행렬 계산, 최적안·대안 선택, 구글맵 링크 생성 |
| E5 설명 | 설명 출처 텍스트(Wikivoyage content, 위키백과 발췌, Wikidata 설명)와 라이선스, 데이터에 있는 한국어 명칭 | 한국어 요약·상세 작성, 번역, 데이터에 없는 한국어 명칭 생성 |
| E6 비용 | 장소별 가격(금액, 무료 여부, 등급 절 소속, 출처), 도시별 숙박·식당 가격 분포, 요금 파일의 1회권 가격, 택시 요금표 | 일정 전체 비용 합산, 예산 수준과 등급 대응, 인원·일수 환산, 범위 산출 |

  나누는 기준은 "데이터로 결정되는 표시는 E1, 사용자 입력이 필요한 판단은 다른 엔진"이다. 그래서 검증되지 않은 장소 표시는 E1이 붙이고 그 감점 폭은 E2가 정하며, 도시별 가격 분포 집계는 E1이 하고 예산 수준 대응은 E6이 한다. 실행 시점(E1은 개발 환경에서 월 1회 일괄, 다른 엔진은 앱 안에서 실행 시), 변경 주기(데이터 갱신과 규칙 변경), 검증 방법(표본 검수와 결과 비교)이 다르기 때문이다.

| 위키백과 발췌 | ko·en·es 문서 제목과 첫 문단 | 위키백과 API(식별 UA, 초당 1회) | 필수(상위 도시·1등급 장소) |
| 페이지뷰 | 월간 덤프 최근 3개월 평균(D-023 확정. 제안 범위 3~6개월 중 디스크·시간 부담이 작은 쪽) | dumps.wikimedia.org (poc/pageviews_extract.py) | 필수 |

## 3. 출력

정적 파일(JSON 또는 압축 JSON, 형식은 5단계 기술 설계). 필드 정의는 `docs/02-data-model.md` 2절.

| 파일 | 내용 | 소비자 |
|---|---|---|
| regions | 지역 계층(상위 8, 지역 59, 하위) | 화면(탐색), E2 |
| cities | 지자체 8,414건의 명칭, 좌표, 인구, 층, 가이드 문서, 숙박 밀도, 가격대 분포, 교통 피드 목록, 요금표 | 화면, E2, E3, E6 |
| places_tier1 | 1등급 장소 전체(추정 5~7만 건) | 화면, E2, E4, E5 |
| places_tier2/<city> | 2등급 장소를 도시별로 분할 | 화면(도시 선택 시 읽기), E2 |
| categories | 상위 범주와 하위 태그 대응표, 취향 선택지 목록 | 화면(R-03), E2 |
| attribution | 소스별 라이선스와 표기 문구, 데이터 갱신일 | 화면(출처 표기) |
| crossval_report | 일치·불일치·단일 출처 통계와 표본 검수 결과 | 문서(품질 기준 확인) |

## 4. 규칙과 알고리즘

1. 수집: PoC 스크립트를 재사용해 소스별 원시 파일을 만든다. 호출 규칙은 poc/README.md(식별 UA, 동시 1개, 초당 1회, 429 대기). 원시 파일은 저장소에 넣지 않는다(D-016).
2. 정규화: 소스별 레코드를 공통 필드로 바꾼다. 명칭은 유니코드 정규화와 공백 정리만 하고 원문을 보존한다. 좌표는 WGS84 소수 6자리. OSM 웨이와 릴레이션은 폴리곤 중심점(PoC는 노드 평균이었으며 중심점으로 바꾼다).
3. 분류 대응: OSM 태그 값, Wikivoyage 유형(see, do, eat, drink, sleep, buy), Wikidata 클래스와 유산 지정 종류를 상위 범주로 대응한다. 한 장소에 범주를 여러 개 허용한다(겸업 장소). 상위 범주는 12개로 확정한다(D-023): 유적·기념물, 종교 건축, 박물관·미술관, 자연·전망, 공원·정원, 해변, 광장·거리, 시장·쇼핑, 식당, 카페·바, 숙박, 체험·공연.
4. 매칭(P-14, C 단계 규칙 유지): 1차 Wikidata QID 키(Wikivoyage wikidata 필드, OSM wikidata 태그). 2차 좌표 150m 안에서 명칭 유사도 0.6 이상(difflib, 스페인어·카탈루냐어·바스크어와 영어 동의어 정규화). 500m 이상 또는 유사도 0.4 미만이면 불일치로 기록하고 병합하지 않는다.
5. 통합 값 선택: 좌표는 OSM과 Wikidata를 Wikivoyage보다 우선한다(검수 4-2 근거). 명칭은 OSM name(현지 공식)을 name_local로, Wikidata 라벨을 es·en으로, name:ca·eu·gl을 따로 보존한다(D-021 ⑥). 영업시간과 가격은 Wikivoyage 값이 있으면 그것을, 없으면 OSM 값을 쓰고 출처를 기록한다. 영업시간은 참고값 표시를 붙인다(D-021 ①).
6. 검증 표시: crossval_status(일치, 불일치, 단일 출처). verified는 단일 출처이고 사이트링크 0이며 조회수 0이면 false(D-021 ⑤). 구글 검수에서 없었던 장소 유형(위성에서 흔적 없는 소규모 OSM 항목)이 여기에 들어간다(추정).
7. 등급(D-023 확정): 1등급은 영문 Wikivoyage 수록, 문화유산 지정, 사이트링크 1개 이상, 또는 조회수 상위 중 하나를 만족하는 장소. 2등급은 이름이 있는 나머지 OSM 장소(식당, 카페, 상점 등). 제외는 이름 없는 객체, 가로수·벤치 같은 잡음 태그, 중복 병합된 하위 레코드.
8. 도시 귀속(D-023 확정): 좌표를 OSM 행정 경계(admin_level 8) 폴리곤에 넣어 지자체를 정한다. 폴리곤이 없으면 Wikidata 지자체 좌표 최근접. 지역은 Wikidata P131 상위와 Wikivoyage 계층을 함께 기록한다.
9. 관심도 신호: 사이트링크 수, 언어별 월평균 조회수, 해외 대표 명소 점수(영어 조회 비중과 사이트링크 수의 조합. 식은 E2 설계에서 정하되 입력값은 E1이 공급)(D-020). 영문 문서 제목 대응 오류(레티로 공원 사례)는 사이트링크 기준으로 제목을 가져와 막는다.
10. 취향 선택지 도출: 상위 범주별 1등급 장소 수를 집계해 선택지와 예시 장소를 만든다.
11. 파일 생성: 3절의 파일로 분할하고 크기를 기록한다. 2등급은 도시별 파일. 전체 크기 목표는 1등급 파일 20MB 이하(압축 전)로 확정한다(D-023).
12. 갱신: 덤프 월간 주기에 맞춰 재실행한다. 재실행은 결정적이어야 한다(같은 입력에 같은 ID). 내부 ID는 QID가 있으면 QID, 없으면 소스 키의 해시.

## 6. 품질 기준과 평가 방법

| 기준 | 목표 | 측정 |
|---|---|---|
| 명칭 정확도 | 층화 표본 36곳 중 29곳 이상(D 단계 수준 유지) | D 단계 방식 재검수(poc/review_gmaps.py, 좌표 핀 병행) |
| 좌표 정확도 | 표본의 95% 이상이 150m 안 | 같은 표본 |
| 분류 정확도 | 표본의 80% 이상 | 같은 표본 |
| 중복 | 1등급 표본 100건 중 중복 2건 이하 | 좌표 50m 안 동일 명칭 쌍 검사 |
| 도시 귀속 | 표본 100건 중 오귀속 2건 이하 | 지자체 경계와 대조 |
| 재현성 | 두 번 실행 결과의 ID와 레코드 수 동일 | 해시 비교 |

평가는 층화 표본(대도시, 중소 관광 도시, 데이터 빈약 소도시 각 12곳)으로 하고 통과 뒤 전수 적용한다.

## 8. 관련 결정

- D-001 유료 데이터 미사용. D-012 엔진 분리. D-013 대안 사다리. D-016 원시 데이터 미커밋. D-020 P-17 용도. D-021 재조정(①⑤⑥⑦ 반영).
- D-023(2026-10-25 설계 동의)으로 확정: (a) 상위 범주 12개, (b) 1등급 기준(Wikivoyage 수록, 유산 지정, 사이트링크 1개 이상, 조회수 상위 중 하나), (c) 도시 귀속은 OSM 행정 경계 폴리곤 후 최근접, (d) 페이지뷰 최근 3개월 평균, (e) 1등급 파일 20MB 이하.
- 결정 필요(남음): (f) Wikivoyage·OSM 파생물의 라이선스 적용 방식. 클로드 제안: 기준 데이터 파일을 앱 공개 저장소에 두면서 Wikivoyage 기반 텍스트 필드는 CC BY-SA 4.0, OSM 기반 장소 파일은 ODbL로 라이선스 파일을 함께 공개한다. 이 제안은 법률 자문이 아니다.
