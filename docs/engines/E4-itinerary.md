# E4. 일정 생성 엔진

- 상태: 초안
- 관련 요구사항: R-14, R-15 (입력으로 R-01, R-02, R-19)
- 관련 결정: D-012, D-013, D-021
- 설계 시점: 3단계
- 작성일: 2026-10-25
- 최종 수정일: 2026-10-25

> E3(설계 동의 D-023)의 이동 시간과 E1의 영업시간 참고값을 입력으로 쓰는 초안이다. 영업시간은 참고값이며 확인 필요 표시를 붙인다(D-021 ①).

## 1. 목적

- 선택한 장소, 이동 시간, 영업시간 참고값, 여행 형태를 입력으로 날짜별 일정을 생성한다. 기간 안에 넣을 수 없는 장소는 초과분으로 표시한다(R-14). 수정 범위를 선택해 재생성한다(R-15).
- 경계: 어느 장소를 고를지는 사용자와 E2, 두 지점 사이 이동 시간은 E3, 비용은 E6. E4는 "언제 어떤 순서로"만 맡는다.

## 2. 입력

| 입력 | 출처 | 필수 |
|---|---|---|
| 기간, 출발·도착 공항과 시각 | R-01 | 필수 |
| 도시별 숙박 일수와 숙박 구역(또는 도시 중심) | E2 제안 또는 사용자 | 필수 |
| 선택 장소 목록(도시, 범주, 좌표, 영업시간 참고값, E2 점수) | R-07, E1 | 필수 |
| 하루 시작·마감 시각, 식사 형태 | R-02 | 필수 |
| 두 지점 이동 시간 함수(수단별 최적안) | E3 | 필수 |
| 고정 항목: 예약 시각(R-19), 비행기·기차 출발 시각 | 사용자 입력 | 선택 |
| 체류 시간(범주별 기본값 또는 사용자 수정값) | 4절 1항, 사용자 | 필수 |
| 재생성 범위: 날짜, 장소, 잠금(순서·시각 고정) 지정 | R-15 화면 | 선택 |

## 3. 출력

- Day[]: 날짜, 도시, 숙박 구역, Item[].
- Item: 장소, 시작·종료 시각, 체류 시간, 직전 장소에서의 이동(수단, 시간, 거리, E3 신뢰도), 영업시간 확인 필요 표시(참고값 없음 또는 참고값과 불일치), 식사 슬롯 여부, 고정 여부.
- 초과분 목록: 넣지 못한 장소와 이유(시간 부족, 도시 불일치, 영업일 불일치 추정).
- 하루 요약: 장소 수, 총 이동 시간, 도보 거리, 시작·종료.
- 소비자: 화면(일정표·지도), E6(식사 수·이동 횟수), E7(저장), R-27(경유지 링크).

## 4. 규칙과 알고리즘

1. 체류 시간 기본값(D-024 확정, 분. 초안의 1.5배): 박물관·미술관 180, 유적·기념물 135, 종교 건축 70, 광장·거리 45, 자연·전망 70, 공원·정원 90, 해변 180, 시장·쇼핑 90, 식당 135, 카페·바 70, 체험·공연 180, 숙박 0. 사용자가 장소별로 바꿀 수 있다.
2. 하루 용량 = 마감 − 시작 − 식사 슬롯. 마감은 항목의 시작 시각에 적용한다(D-024). 시작 시각이 마감 이전이면 종료가 마감을 넘어도 배치한다(예: 마감 22시, 21시 30분에 1시간짜리 항목 시작 가능). 식사 슬롯(결정 필요): 점심 75분(12:30~14:30 사이), 저녁 90분(19:30 이후). 식사 형태 "가볍게"는 각 15분 단축, "간식 포함"은 16시 전후 30분 추가. 식당·카페 장소를 선택했으면 그 장소가 슬롯을 채우고, 없으면 빈 슬롯으로 둔다.
3. 도시 배분: 숙박 일수대로 날짜를 도시에 할당한다. 도시 간 이동이 있는 날은 이동 시간(E3 도시 간 최적안)을 빼고 남은 시간을 용량으로 쓴다. 첫날은 도착 시각, 마지막 날은 출발 시각 3시간 전까지(비행기) 또는 1시간 전(기차)으로 자른다(결정 필요).
4. 묶기: 도시 안 선택 장소를 날 수만큼 지리적으로 묶는다. 좌표 k-means(k = 그 도시의 일수, 씨앗 고정)로 초기 묶음을 만들고, 각 묶음의 체류·이동 합이 용량을 넘으면 점수가 낮은 장소를 인접 묶음 또는 초과분으로 옮긴다.
5. 하루 순서: 숙박 구역(없으면 도시 중심)에서 출발해 최근접 이웃으로 순서를 만들고 2-opt로 개선한다. 이동 시간은 E3 최적안(도보 1.5km 이하는 도보).
6. 시간 배치: 시작 시각부터 이동과 체류를 누적한다. 다음 항목의 시작 시각(이동 포함)이 마감을 넘으면 그 항목부터 다음 날 또는 초과분으로 보낸다. 영업시간 참고값이 있는 장소가 닫힌 시간에 걸리면 같은 날 안에서 순서를 한 번 바꿔 본다. 그래도 안 되면 그대로 두고 "확인 필요"를 붙인다. 참고값이 없는 장소는 기본값으로 배치하고 "확인 필요"를 붙인다(D-021 ①).
7. 고정 항목: 예약 시각과 교통 출발 시각은 먼저 자리를 잡고 나머지를 앞뒤에 채운다. 고정 항목끼리 겹치면 경고하고 생성하지 않는다.
8. 초과분: 용량을 넘는 장소는 E2 점수가 낮은 것부터 뺀다. 초과분은 이유와 함께 목록으로 보여 사용자가 교체할 수 있게 한다.
9. 재생성(R-15): 수정 종류는 여섯 가지이고 종류마다 다시 계산하는 범위가 다르다. 사용자가 손으로 바꾼 것은 잠금으로 취급한다.

   | 수정 종류 | 사용자 동작 | 재생성 때 처리 |
   |---|---|---|
   | 장소 추가·제거 | 선택 목록에서 넣고 빼기 | 해당 날짜만 다시 계산 |
   | 체류 시간 변경 | 항목의 체류 시간 수정 | 그 항목 이후 시각만 밀기. 순서 유지 |
   | 방문 순서 변경 | 항목을 끌어 재배열 | 사용자가 정한 순서를 잠금으로 간주하고 시각만 다시 계산 |
   | 날짜 이동 | 항목을 다른 날로 옮기기 | 두 날짜만 다시 계산 |
   | 날짜 단위 재생성 | 특정 날 선택 후 재생성 | 그 날의 잠기지 않은 항목만 순서·시각 재계산 |
   | 잠금 | 항목의 순서·시각 고정 | 입력으로 취급해 바꾸지 않음 |

10. 결정성: 같은 입력에 같은 출력. k-means 씨앗 고정, 동률은 내부 ID 순.

## 5. 데이터 의존

| 데이터 | 출처 | 비고 |
|---|---|---|
| 영업시간 참고값 | E1(OSM, Wikivoyage) | 보유율 박물관 21.6%, 식당 15.3%, 명소 5.5%. 참고값 |
| 이동 시간 | E3 사전 계산과 실행 시 추정 | 신뢰도 표시를 그대로 전달 |
| 장소 점수 | E2 | 초과분 결정에 사용 |

새 외부 소스는 없다.

## 6. 품질 기준과 평가 방법

| 기준 | 목표 | 측정 |
|---|---|---|
| 시간 준수 | 모든 항목의 시작 시각이 하루 시작 이후, 마감 이전 100% | 자동 테스트 |
| 이동 비율 | 하루 총 이동 시간이 용량의 40% 이하(결정 필요) | 생성 결과 집계 |
| 확인 필요 표시 | 참고값 없는 항목 100%에 표시 | 자동 테스트 |
| 사용자 조정 | 스페인 계획 수립 때 생성 뒤 수동으로 옮긴 항목 20% 이하 | 편집 기록 |
| 재생성 | 잠긴 항목 불변 100%, 범위 밖 항목 불변 100% | 자동 테스트 |

## 7. 대안 사다리

| 상황 | 대안 |
|---|---|
| 이동 시간 없음 | E3의 직선 거리 추정 사용, 신뢰도 "추정" |
| 영업시간 없음 | 기본값 배치 + 확인 필요 표시(확정, D-021 ①) |
| 숙박 구역 없음 | 도시 중심에서 출발 |
| 선택 장소가 용량의 2배 초과 | 생성 전에 경고하고 초과분 비율을 먼저 보여 준다 |

## 8. 관련 결정

- D-012 엔진 분리. D-013 대안 사다리. D-021 ①(영업시간 참고값). D-024(체류 시간, 마감 기준, 수정 종류).
- D-024 확정: (a) 체류 시간 기본값표(초안의 1.5배), 마감은 시작 시각 기준, 수정 종류 여섯 가지.
- 결정 필요: (b) 식사 슬롯 길이와 시간대, (c) 첫날·마지막 날 자르는 여유(비행기 3시간, 기차 1시간), (d) 이동 비율 상한 40%, (e) 하루 수용 장소 수 기본값(E2와 공유. 제안: 용량 ÷ 평균 체류 135분 ≈ 3~4곳).
