# 작업 분해 기반 일정 추정 (T-009)

D-014에 따라 2단계 PoC 완료 시점에 작업을 분해해 11월 완료 가능 여부를 판단하는 자료다. 결론은 사용자가 채택한다(D-019 결정 지점). 작성일 2026-10-21.

## 1. 전제와 측정값

- 목표(사실): 2027년 5월 스페인 여행 계획을 이 프로그램만으로 세우고, 숙소 예약을 위해 그 계획이 2026년 11월에 완료되어야 한다(요구사항 11절).
- 따라서 앱으로 계획을 세우는 시간(추정 7~10일. 후보 탐색, 선택, 일정 생성, 숙박 결정)을 11월 안에 넣으려면 앱은 11월 20일 전후에 쓸 수 있어야 한다(추정).
- 남은 기간(사실): 2026-10-22부터 11-30까지 40일. 11-20까지 30일.
- 측정된 진행 속도(사실, git log와 docs/TASKS.md·decisions.md):
  - 2026-10-17 ~ 10-21의 5일 동안 커밋 22건, 결정 20건, 완료 과업 8건과 T-006의 다섯 단계(A~E). 작업 단위로 약 13개, 하루 약 2.6단위.
  - 사용자 왕복(결정 또는 "진행" 동의)은 결정 20건만 세어도 하루 4회, 동의와 수정 요청을 더하면 하루 6~7회로 추정된다.
- 지금까지는 문서와 PoC 작업이었다. 개발 단계의 작업 단위는 구현과 검증이 포함되어 단위당 시간이 더 길다(추정 1.5배).

작업 단위의 뜻: 계획 제시 → 동의 → 작업 → 검증 → 보고의 한 번. 사용자 왕복은 그 단위 안의 결정·동의 횟수다.
