## 1. 정보 구조

```
앱
├─ 여행 선택 (저장소 주소·Key 입력, 최근 여행)
└─ 여행 하나
   ├─ S1 입력      : 기본 정보, 여행 형태, 취향
   ├─ S2 요약      : 도시·지역 요약, 선호 프로필
   ├─ S3 탐색·추천 : 계층 탐색, 추천 목록, 세 수준 대안, 지도
   ├─ S4 선택·배치 : 선택 목록, 날짜 배치, 숙박 계획
   ├─ S5 일정표    : 날짜별 일정, 이동, 확인 필요, 초과분, 재생성, 비용 패널
   ├─ S6 장소 상세 : 명칭 병기, 설명·음성, 영업시간·가격·예약, 출처, 구글맵 링크 (S3·S5에서 겹쳐 열림)
   ├─ S7 공유      : 제안 목록, 승인·거절, 내보내기·가져오기, My Maps 파일, 경유지 링크
   └─ S8 설정      : 저장소·Key·토큰, 역할, 버전, 출처 표기
```

하단 탭(세로 화면)은 입력, 탐색, 일정, 공유, 설정 다섯 개다. S2는 입력 완료 뒤 탐색 탭의 첫 화면으로, S4는 탐색과 일정 사이의 단계 화면으로, S6은 겹쳐 열리는 상세로 둔다. 화면 수는 일정 추정의 8개와 같다.

## 3. 화면 흐름

```
여행 선택 ─(새 여행: 저장소·Key·토큰)─▶ S8 설정 ─▶ S1 입력
여행 선택 ─(기존 여행: 저장소·Key)──────────────▶ S5 일정표 (최신 버전 자동 읽기)

S1 입력 ─완료─▶ S2 요약 ─▶ S3 탐색·추천 ⇄ S6 상세
S3 ─선택 완료─▶ S4 선택·배치 ─생성─▶ S5 일정표 ⇄ S6 상세
S5 ─재생성(범위 선택)─▶ S5
S5 ─비용 패널 / 초과분 서랍 (같은 화면)
S5, S4 ─저장─▶ E7 커밋 (충돌 시 경고 선택지)
S7 공유: 어느 화면에서나 탭으로. 서브는 S3·S5의 항목에서 "제안" 동작으로 S7에 기록
```

- 첫 사용(메인): 여행 선택 → S8에서 저장소·Key·토큰 입력 → S1 → S2 → S3 → S4 → S5. 요구사항 4절의 6단계 흐름과 같다.
- 공유자: 링크로 열어 Key 입력 → S5 일정표. S1~S4는 열람만.
- 서브 수립자: 공유자와 같되 S3·S5에서 제안 작성 가능, S7에서 자기 제안 상태 확인.

## 4. 화면 공통 규칙

- 영업시간이 확인되지 않은 항목은 모든 화면에서 같은 표시(D-021 ①). 검증되지 않은 장소도 같은 표시(D-021 ⑤).
- 명칭은 한국어(있으면) + 현지어·영어 병기. 바스크어·카탈루냐어·갈리시아어 지역은 현지 명칭 + 스페인어(D-021 ⑥).
- 모든 추정값(이동 시간 추정, 비용 범위)은 신뢰도 표시와 근거 문구를 함께 보인다.
- 출처 표기는 장소 상세와 설정 화면 두 곳에 둔다(P-13).
- 저장은 수립자의 명시 동작 또는 유휴 자동 저장(E7). 공유자 화면에는 저장 동작이 없다.
